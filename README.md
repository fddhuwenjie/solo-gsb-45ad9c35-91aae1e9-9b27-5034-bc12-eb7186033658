# 城市雨洪调蓄池泄放序列推演台

按时段搜索闸门开度序列的调度推演工具：**先保证调蓄池不溢流，再在所有可行序列中最小化下游安全流量超标总量**，并逐时段展示库容、实际出流、触发的约束事件及无解原因。另提供**容量反算（容量规划）**：沿用同一组入流、闸门档位、切换间隔与初始状态，另填允许的下游超标总量与设计容量上界，求出满足超标预算且全程不溢流的**最小设计库容**。

- **后端**：Python 3.12 + FastAPI + SQLite（无 ORM，标准库 `sqlite3`）
- **前端**：原生 HTML / CSS / JavaScript（零构建、零前端框架，纯 SVG 自绘图表）
- **求解器**：基于 `(档位, 已保持时长, 时段末库容)` 的动态规划精确搜索 + **无损 Pareto 支配剪枝**（前沿完整保留，绝不抽稀；要么给严格最优，要么明确拒绝）；库容状态以**输入精度自适应的十进制量子精确整数**表示，水量平衡/容量判定零舍入
- **容量反算**：可行性关于容量单调、逐次精确判定，在接口输入的共同十进制量子整数格上二分求最小设计库容，并给出已证实的不可行下界与可行上界

前置：本机已安装 Docker（含 Compose 插件）。

```bash
docker compose up --build
```

## 功能与页面

### 录入参数（左侧）
| 参数 | 含义 |
|---|---|
| 时间步长 | 入流预测与调度的离散时段（页面按分钟填写，内部转秒） |
| 调蓄池容量 / 初始库容 | 库容上限 `Vmax` 与预报开始时的存量 `V0`（m³） |
| 下游安全流量上限 | 河道可安全承泄的最大流量 `Qsafe`（m³/s） |
| 闸门开度档位 | 离散档位的过流能力序列（m³/s），可增删，自动排序去重 |
| 切换最小间隔 | 每次换到新档后，该档至少连续保持的时段数 `K` |
| 预报开始时闸门档位 | 初始现状档位（1 基） |
| 现状档已保持时长 | 现状档此前已连续保持的时段数；填 `0` = 刚切到位（须等满 `K` 才能再换），填 `≥K` = 当前可立即切换 |
| 分时段入流预测 | 每个时段的入流量 `I(t)`（m³/s），可随时增删时段 |

### 操作
- **▶ 立即推演**：用当前表单参数计算，不入库（快速试算）。
- **保存场景**：把参数存入 SQLite；之后可点场景名载入。
- **更新当前场景**：把参数写回当前场景并执行一次持久化推演。
- 左侧场景列表显示最近推演是否可行（绿点/红点），可回看最近 5 次历史推演结果。
- **任意参数修改后再次点击推演即重算**。

### 容量反算（容量规划，左侧「容量反算」区块）
面向方案设计：沿用上方已填的入流预测、闸门档位、切换最小间隔与初始状态（**「调蓄池容量」字段不参与**，容量正是待求的设计值），另填两项：

| 参数 | 含义 |
|---|---|
| 允许的下游超标总量 | 设计所允许的下游超标水量预算 `B`（m³） |
| 设计容量上界 | 反算只在该上界 `Cmax` 之内搜索最小库容（m³） |

点击 **▶ 反算最小设计库容**（`POST /api/size-capacity`，不入库）后，右侧展示：
1. **结论横幅**：最小设计库容（或上界内不可行的原因 / 规模拒绝）。
2. **指标卡**：最小设计库容、已证实不可行下界、已证实可行上界、超标预算、见证序列超标总量、二分试算次数。
3. **容量搜索区间**：单调可行性 + 量子级精确二分的收敛区间（不可行下界 / 可行上界 / 区间宽度 = 1 个量子 / 物理下界 / 容量上界）与逐次试算记录表（试算容量、判定、该容量下最小超标、上界收紧说明）。
4. **见证序列**：最小容量处按现有字典序目标选出的最优开度序列——库容过程图、入流/出流过程图、逐时段明细表（与推演结果同一套展示与一致性安全网复核）。

### 结果展示（右侧）
1. **结论横幅**：可行 / 无解。
2. **指标卡**：超标总量（优化目标）、库容峰值及利用率、出流峰值、切换次数、超标时段数、末库容。
3. **库容过程图**：时段末库容曲线，标注容量上限（红虚线）与 90% 高水位线。
4. **入流 / 出流过程图**：实际出流受"档位能力"与"库内存水"双重限制；红色阴影标出超标区段，绿虚线为安全上限。
5. **逐时段明细表**：选定档位、实际出流、时段初/末库容、库容利用率条、本时段超标水量，以及**触发约束/事件**：
   - `SWITCH` 档位切换；`LOCKED` 切换锁定中不能换档；
   - `EXCEED` 下游超标（含超标水量）；
   - `FULL` 库容打满临界 / `HIGH` 高水位（≥90%）；
   - `EMPTY` 库内水量不足、实际出流低于档位能力；`NORMAL` 一切正常。
6. **搜索过程统计**：溢流剪枝次数、首次剪空时段、最大层状态数、最大单桶前沿点数、`exact` 是否精确解（恒为 `true`）。

## 求解模型

### 水量平衡（逐时段）

```
V(t+1) = V(t) + I(t)·Δt − R(t)
R(t)   = min( 所选档位过流能力·Δt ,  V(t) + I(t)·Δt )
```

第二项体现物理约束：库中没有那么多水时，闸门开得再大也放不出来。

### 硬约束（按优先级）
1. **任意时段末库容 `V(t+1) ≤ Vmax`**（绝对不溢流）；
2. **切换最小间隔**：从初始现状档及其已保持时长出发，每次换到新档后必须连续保持至少 `K` 个时段（`K=1` 即每时段都可切换）。

### 优化目标（在全部不溢流的序列中按字典序比较）
1. 下游超标总量 `Σ max(0, R(t) − Qsafe·Δt)` 最小；
2. 并列时闸门切换次数最少；
3. 再并列时峰值出流、峰值库容更小。

### 搜索方法
以 `(当前档位, 已连续保持时长, 时段末库容)` 为状态做动态规划，每个状态保留完整代价元组 `(累计超标, 切换次数, 峰值出流, 峰值库容)`，末端按字典序取全局最优后回溯出开度序列。

- **库容状态的精确整数表示**：接口参数都是有限十进制。求解前把容量、初始库容、各单时段水量（流量×步长，含安全流量）统一换算到输入精度自适应的十进制量子（10^-D m³，D 取上述各量的最大小数位）下的精确整数；归并键就是精确库容本身，容量判定是严格整数比较。**没有固定放大倍数、也没有任何容差**：超容哪怕只有一个量子（如 2e-5 m³）也会被判为溢流，末库容恰好等于容量则合法。接口允许任意精度的小数（如容量 99999.99998 m³、入流 0.000001 m³/s、步长 2.5 s），水量平衡在该精度下严格一致。
- **无损 Pareto 支配剪枝**：同一 `(档位, 保持时长)` 桶内，若状态 A 的时段末库容不高于 B，且 A 的**完整代价元组字典序不劣于** B，则 B 对任何后续档位序列都不可能更优（库容单调映射 + 字典序首个不同分量的严格性被追加量保持），可安全删除。剪枝后前沿按库容升序时代价元组严格递减，一次扫描 O(k log k) 得到。
- 桶数封顶在 `档位数 × (K+1)`（已保持时长达 `K` 后状态等价）。
- **前沿完整保留，绝不抽稀**：不存在任何"等距丢弃中间状态/截断前沿"的有损环节。因此只要返回 `feasible=true`，`objective` 一定是字典序严格最优，页面与 `prune_stats.exact` 均标注为精确解。48 时段 × 10 档场景单桶前沿可达 1000+ 点，照样无损精确求解。
- **页面一致性安全网**：前端在展示"精确可行"结论前，会按原始参数复核逐时段容量与水量平衡；任何超容/不守恒的结果都不会被标注为精确可行。

### 规模拒绝（不把近似值标成最优）
精确求解需要保留全部 Pareto 前沿用于回溯。为防止超大输入耗尽内存，设有三个**资源保护上限**（`app/engine.py`）：

| 常量 | 默认值 | 含义 |
|---|---|---|
| `DEFAULT_MAX_STATES` | 300,000 | 单个时段剪枝后状态数 |
| `DEFAULT_MAX_TOTAL_STATES` | 1,800,000 | 累计保留状态数（决定回溯总内存，单状态约 160B） |
| `DEFAULT_MAX_RAW_STATES` | 1,000,000 | 单层剪枝前原始状态数（生成期瞬时内存保护，生成过程中触限即中止） |

触及任一上限时，接口返回 `feasible=false` 且 `infeasible.code="SEARCH_LIMIT"`（HTTP 仍是 200；这**不是"无解"，也不是最优解的近似**，而是"该规模未在保护预算内完成精确求解"的明确拒绝），并给出缩小规模的建议，不返回任何开度序列或目标值。前端以橙色"规模拒绝"横幅与拒绝原因卡片展示。缩小输入（时段数/档位数/增大间隔）后重试即可正常得到精确解。

### 容量反算模型（单调可行性 + 量子级精确二分）

容量反算把推演问题反过来：容量 `C` 不再是输入，而是待求的设计值。定义可行性谓词

```
F(C) = 容量 C 下存在不溢流、且下游超标总量 ≤ 预算 B 的开度序列
```

- **精确判定**：`F(C)` 由 `_search` 的字典序最优结果判定——有不溢流解且最优超标总量（整数量子）`≤ B`。比较是严格整数比较，零容差。
- **单调性**：容量增大时不溢流序列集合单调扩张、最小超标总量单调不增，故 `F` 关于 `C` 单调，二分合法。
- **共同十进制量子**：容量上界、初始库容、超标预算与各单时段水量（流量×步长）一起决定量子 `10^-D m³`；二分在该量子整数格上进行，区间收敛到恰好 **1 个量子**时，`hi` 即量子意义下的最小设计库容。
- **已证实的上下界**：下界 `lo` 由物理论证（低于 `max(初始库容, 满管泄放最低轨迹峰值)` 必溢流）或精确试算证实不可行；上界 `hi` 经精确试算证实可行。响应同时返回 `proven_infeasible_below_m3`（不可行下界）与 `proven_feasible_at_m3`（可行上界 = 最小容量）。
- **上界收紧**：容量 `mid` 处最优序列的峰值库容为 `pv` 时，该序列在 `max(pv, V0)` 处即可行，且由于可行集随容量单调扩张，它在该处仍是字典序最优——`hi` 因此可直接收紧到 `max(pv, V0)`，无需重新搜索，不丢最优性。
- **见证序列**：最小容量处按现有字典序目标（超标总量→切换次数→峰值出流→峰值库容）选出的最优开度序列，结构与 `solve()` 的可行结果完全一致（逐时段轨迹、事件标注、`prune_stats`）。
- **规模拒绝的传播**：任一容量试算（上界检验、二分试算、锁定诊断子搜索）触及 `SEARCH_LIMIT` 资源上限时，**整个请求立即返回规模拒绝**——绝不把未完成的试算当作不可行继续收缩区间，也绝不返回近似容量。

### 无解 / 拒绝诊断
| code | 含义 | 系统给出的建议 |
|---|---|---|
| `ALREADY_OVERFLOW` | 预报开始时 `V0` 已超过容量（容量反算中：超过设计容量上界） | 核实初始库容 / 扩容（或提高容量上界） |
| `OVERFLOW_UNAVOIDABLE` | 即使忽略一切切换约束、每时段都以最大档位满管泄放仍会溢流——满管泄放得到的是逐时段最低库容轨迹，故任何序列都无解（容量反算中：上界之内不存在不溢流的设计容量） | 二分计算所需的最小最大泄流能力、首次溢流的库容缺口（扩容方量）、上游削峰错峰；并绘制满管泄放库容轨迹图 |
| `LOCKED_INTERVAL` | 无切换限制时不溢流，**但初始现状档位 + 最小间隔锁定导致来不及提闸**（纯调度约束型无解；容量反算中：即使容量取到上界仍被迫溢流） | 二分给出"现状档还需保持多久才可行"、减小 `K`、增加高档泄流能力、提高容量上界容纳锁定期间累积水量、错峰 |
| `BUDGET_UNATTAINABLE` | **仅容量反算**：上界容量下有不溢流序列，但其最小超标总量仍超过允许预算；最小超标随容量单调不增，故上界之内无满足预算的设计 | 提高设计容量上界、放宽超标预算（响应附 `min_exceed_at_upper_m3` 与 `deficit_m3`）、增加高档泄流能力、错峰 |
| `SEARCH_LIMIT` | **规模拒绝**：精确求解触及资源保护上限；未做抽稀、未返回近似值（容量反算中任一试算触限即整体拒绝，不收缩区间） | 减少时段数、合并相近档位、增大切换最小间隔 |

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| POST | `/api/solve` | 按请求体参数即席推演（不入库） |
| POST | `/api/size-capacity` | 容量反算（不入库）：求满足超标预算且全程不溢流的最小设计库容 |
| GET/POST | `/api/scenarios` | 场景列表 / 新建场景 |
| GET/PUT/DELETE | `/api/scenarios/{id}` | 场景详情（含最近推演）/ 更新 / 删除（级联删历史） |
| POST | `/api/scenarios/{id}/run` | 对已保存场景执行一次推演并留存 |
| GET | `/api/scenarios/{id}/runs` | 该场景的推演历史 |
| GET | `/api/runs/{id}` | 取回某次历史推演完整结果 |

请求/响应字段见 `app/main.py` 中的 Pydantic 模型，完整结果结构见 `app/engine.py:solve()` 与 `app/engine.py:size_capacity()`。

### `POST /api/size-capacity` 接口规则

**请求体**（`CapacitySizingInput`）：沿用推演的 `initial_storage_m3`、`dt_s`、`q_safe`、`min_interval`、`initial_opening_index`、`initial_held`、`openings`、`inflows`（含义与校验规则同 `/api/solve`），**不含 `capacity_m3`**，另加：

| 字段 | 约束 | 含义 |
|---|---|---|
| `capacity_upper_m3` | `> 0` | 设计容量上界：只在该上界之内搜索最小库容 |
| `exceed_budget_m3` | `≥ 0` | 允许的下游超标总量预算 |

**可行响应**（`feasible=true`，HTTP 200）：

| 字段 | 含义 |
|---|---|
| `min_capacity_m3` | 最小设计库容（共同十进制量子意义下精确） |
| `witness` | 最小容量处的见证序列结果，结构同 `solve()` 可行响应（`steps`/`summary`/`objective`/`prune_stats`，其 `params.capacity_m3` 即最小容量） |
| `search.proven_infeasible_below_m3` | 已证实的不可行下界（不超过该容量必不可行；`null` 表示 0 容量即可行） |
| `search.proven_feasible_at_m3` | 已证实的可行上界（= 最小设计库容） |
| `search.interval_width_m3` / `quantum_m3` | 收敛区间宽度（恒为 1 个量子）/ 量子大小 |
| `search.physical_min_lower_bound_m3` | 物理下界：`max(初始库容, 满管泄放最低轨迹峰值)` |
| `search.trials` | 逐次试算记录（容量、判定、该容量最小超标、上界收紧说明） |

**不可行响应**（`feasible=false`，HTTP 200）：`infeasible.code` 为 `ALREADY_OVERFLOW` / `OVERFLOW_UNAVOIDABLE` / `LOCKED_INTERVAL` / `BUDGET_UNATTAINABLE` 之一，附原因与建议；任一试算触及资源上限时返回 `SEARCH_LIMIT` 规模拒绝（不返回 `min_capacity_m3` 或 `witness`）。参数校验失败返回 HTTP 422。
